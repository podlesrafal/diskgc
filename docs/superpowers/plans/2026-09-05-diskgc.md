# diskgc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Swift CLI (`diskgc`) plus LaunchAgent that reclaims disk space automatically from tool caches and build artifacts under pressure, and asks the user before touching Docker resources or git worktrees.

**Architecture:** `DiskGCCore` library: scanners produce `Candidate`s by shelling out to `du`/`git`/`docker`/`lsof`; a `PressurePlanner` orders auto candidates; one `Executor` validates paths and performs every deletion, journaling first. `diskgc` executable wires ArgumentParser commands to the core. Everything that touches the real system goes through `ShellRunner`/`FileManager` so tests use a `FakeShell` and temp directories.

**Tech Stack:** Swift 6 toolchain, Swift 5 language mode, SwiftPM, swift-argument-parser, Yams, Swift Testing (`import Testing`).

**Spec:** `docs/superpowers/specs/2026-09-05-diskgc-design.md`

## Global Constraints

- macOS 14+, arm64, Swift tools 6.0 with `swiftLanguageMode(.v5)` on every target.
- Dependencies: `swift-argument-parser` and `Yams` only.
- Never call `docker system prune`; never pass `--force` to `git worktree remove`.
- Every deletion goes through `Executor`; every action is journaled before it runs.
- No comments in code except `// TODO(scope):` or a one-line workaround note.
- Commits: conventional commits, English, no trailers.
- Default config values exactly as in the spec (target_free_gb 60, notify_min_gb 5, notify_cooldown_hours 24, rescan_hours 6, inactive days 7/21/3/14/30/14).

### Task 5: Executor

**Files:**
- Create: `Sources/DiskGCCore/Executor/Executor.swift`
- Test: `Tests/DiskGCCoreTests/ExecutorTests.swift`

**Interfaces (Produces):**

```swift
public struct ExecutionResult: Equatable { public var candidate: Candidate; public var ok: Bool; public var message: String }
public struct Executor {
  public init(shell: ShellRunner, fs: FileManager, never: [String], journal: Journal, dryRun: Bool, now: @escaping () -> Date = Date.init)
  public func execute(_ c: Candidate) -> ExecutionResult
  public static func describe(_ a: Action) -> String     // "rm -rf /p", "uv cache clean", "git -C r worktree remove p"
}
```

Behaviour: for each action in order — `removeDirectory`: `PathSafety.validate` then `fs.removeItem`; `removeContents`: validate then remove each child; `run`: `shell.run(command, args, cwd: nil)` and fail when status != 0; `worktreeRemove`: `git -C repo worktree remove path`; `worktreePrune`: `git -C repo worktree prune`. A journal entry is appended before each action (ok = false, error nil) and updated after? No: simpler — append one entry per action after the attempt, but append a `dryRun`/`planned` entry first only in real mode. Decision: append exactly one entry per action **before** executing with `ok: false, error: "pending"`, then one after with the result. In dry-run append one entry with `dryRun: true`, `ok: true`.

- [ ] Tests with temp dirs and FakeShell: dry-run does not delete and journals `dryRun: true`; real run deletes directory; refusal on symlink leaves target intact and journals `ok: false`; `run` action with non-zero status yields `ok: false`; `worktreeRemove` calls `git -C repo worktree remove path` with no `--force`; `describe` strings.
- [ ] Commit `feat: add executor with safety validation and journaling`
